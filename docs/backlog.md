# backlog — things noticed during a phase that are not that phase's DoD

Constitution rule 9: nothing here is picked up before phase 6's DoD is green. One line each: where it was seen · what · the fix if known.

- **2026-09-06 · phase 6 build · qa:cases cannot supply a path id** — a step is not runnable when `API.path` holds `{id}`, so every confirm/edit/delete endpoint stays out of reach even now that the resource segment is right: TC-rental-005/006 (`/api/bookings/{id}/confirm`) and eight more. `TC.data` already carries the golden row; it could carry the id a prior step created, or `run` could thread the previous step's response into the next one's path.
- **2026-09-06 · phase 6 build · qa:cases false pass on an exception flow** — a non-main flow expects `4xx`, and an endpoint answers 400 to a body it cannot parse, so TC-rental-004 (BR-rental-006@v1 maintenance) passed on `HTTP_STATUS=400` with an empty request and never exercised the rule. `expect` for an exception flow should name the status and the `title`/`rule` the refusal must carry, not any 4xx. Same root as the http-body line above.
- **2026-09-06 · phase 6 build · RentPoint api has no auth** — every `API` record says `auth: "required"` and nothing implements it; `POST /api/bookings/{id}/confirm` takes `by` from the request body, so the BR-rental-010@v1 audit records whatever the caller types, and any caller can confirm any booking. TSK-001 set the pattern (`by: customer:{req.CustomerId}`) and TSK-002 followed it. Auth belongs to a TSK of its own, from ACL-014/ACL-035/ACL-047 and `project.json.apps[].auth`; until then the slice is a fixture, not a system.
- **2026-09-06 · backlog B · `change:impact` treats `refs` as a dependency** — `dependents()` walks every edge, and core writes a `refs` edge for any known id that appears anywhere in a record. So CR-004 (touching one scenario) pulled in TSK-001 and its 17 IMPs because the dev slice printed SCN-rental-001, and DEF-rental-001/003 because their reproduce text names it: 22 affected and 19 `G-change-005` freeze warns for a change that adds a scenario. A dependency is a named edge (`covers` `implements` `verifies` `displays` `serves`); `refs` is "mentions". Fixing the walk changes what every past impact would have said, so `docs/dod/phase-3.md` has to be re-verified with it — that is the whole job, not a flag.
- **2026-09-06 · backlog B · `qa:finding --kind` defaults to `rule`** — a finding routed to design opens its CR with `kind: rule`, which `impact` reads as "re-versions the BR and everything that enforces it" → lane full. CR-004's real request was "add the boundary scenario nobody wrote", which is not a rule change at all; it took a `change:open --amend` to correct. Either the default becomes `other` (the kind with no discriminator, where the owner names the lane) or `finding` asks for `--kind` when the routing is design.
- **2026-09-06 · backlog A · one `API.sample` cannot serve every scenario of an endpoint** — the sample is one declared call, so it fits one golden row and one flow. On RentPoint API-019's sample fits GD-rental-001 "3 วัน" (เครื่องตบดิน, 800/วัน) and nothing else: SCN-rental-002 (maintenance) needs a different equipment id, SCN-rental-018 needs the 1,250/วัน one, and SCN-rental-019/020 are golden rows of CALC-002 whose input is a fee, not dates — those two are unit-test territory (brief §5.6: unit = dev, E2E = qa) and may never belong to an http step at all. Next shape: a list of samples each naming the golden row or flow it serves, picked by `match.label`/`SCN.flow`.
- **2026-09-06 · backlog A · a sample gap is routed to dev** — `cases` writes `routing: dev` for every case it cannot make runnable, as the SPEC says ("a DEF routing: dev per TC it could not make runnable"). But "API-019.sample does not cover this scenario" is a declaration nobody wrote, not code that misbehaves: DEF-rental-006..009 point dev at work that belongs to whoever writes `--records`. Either the SPEC gains a second routing for a declaration gap, or `cases` reads the gap text and routes design when the missing record is a design one.
